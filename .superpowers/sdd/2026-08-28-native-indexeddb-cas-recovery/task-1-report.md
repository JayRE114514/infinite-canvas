## Architectural invariants checked

- Import purity: `createRecoveryDatabase` opens nothing at import or construction time; `factory.databases()`
  is empty until `run()` (test 2). Opening is lazy and coalesced through a single `opening` promise.
- Injected factory only: core tests pass an explicit `IDBFactory`; no ambient global is read, so the setup file
  cannot hide an ambient dependency. `environment: "node"` with no DOM polyfill enforces this.
- Fixed version 1 schema: three stores, `drafts` keyed `["scopeId","draftId"]`, `markers` keyed
  `["scopeId","markerId"]`, `epochs` keyed `"scopeId"`, exactly one `by_scope` index on drafts and markers,
  nothing else (test 1 asserts version, store set, key paths and index names).
- Every failure is bounded and typed: `blocked` resolves well under `RECOVERY_OPEN_TIMEOUT_MS` (asserted against
  `performance.now()`), and no path can hang without a deadline or an abort.
- Deadline aborts rather than merely rejecting, so a late commit after timeout is impossible (mutation 1 proves it).
- Owner cancellation via `AbortSignal` aborts and rolls back, returning `aborted`; the signal is checked before
  open, after open, and at listener registration, and the listener is removed on settle.
- Work-function throw rolls back all writes in the transaction, including writes to multiple stores.
- `oncomplete` returns `ok` only when `work` actually produced a value; a commit without a produced value is
  reported as `error` rather than a fabricated success.
- One-transaction discipline is explicit in the `RecoveryTxn` contract and comments: `work` may await only
  `txn.req(...)`, because an external await after the request queue drains permits IndexedDB auto-commit.
- Never the blocker for a newer tab: `onversionchange` closes immediately and clears the cached connection;
  `onclose` also clears it. The upgrade test's `onblocked` branch is the guard (mutation 2 proves it).
- Test-surface containment: the `include` glob admits only `src/services/**/*.test.ts`, so no DOM/React component
  test can appear without editing `vitest.config.ts`.
